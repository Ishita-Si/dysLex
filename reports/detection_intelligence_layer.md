# Phase 2.5 Detection Intelligence Layer Implementation Report

DysLexAI Phase 2.5 adds an inference-only intelligence layer on top of the already-trained MVP models. The layer does not retrain models; it loads serialized model artifacts, computes or loads a non-dyslexic reference baseline, compares each assessment with that baseline, infers learning weaknesses, creates a learning profile, and maps weaknesses to intervention category identifiers.

## Reference Baseline Calculation

The baseline is generated by `python -m src.mvp.intelligence` or by calling `POST /baseline-reference/regenerate`.

Process:

1. Load processed MVP feature tables from `datasets/processed/mvp_*_features.csv`.
2. Keep only rows where `label == 0`, representing the non-dyslexic reference group.
3. Ignore identifier and metadata columns: `label`, `data_source`, `subject_id`, and `participant_id`.
4. For each numeric feature, calculate:
   - mean
   - median
   - population standard deviation
5. Store the result in `models/mvp/baseline_reference.json`.

The stored JSON is intentionally simple so the API, dashboard, and intervention repository can reuse it directly.

## Weakness Inference

Weaknesses are inferred with rules, not another ML model. Each feature has metadata that defines:

- plain-English name
- risk direction (`higher` or `lower`)
- associated modality
- associated learning weakness

During inference, user feature values are compared with reference means using standard-deviation distance. A feature-level severity is assigned:

- `High`: risk-direction deviation is at least 2 standard deviations from reference
- `Moderate`: risk-direction deviation is at least 1 standard deviation from reference
- `Low`: deviation is below the moderate threshold

Model probabilities then add modality-level evidence. Higher reading, writing, or typing probabilities strengthen the weaknesses linked to that modality.

## Learning Profile Generation

The learning profile combines feature deviations and model probabilities into five clinically interpretable dimensions:

- `reading_fluency`
- `letter_reversal`
- `spelling_accuracy`
- `typing_accuracy`
- `phonological_processing`

Each dimension is returned as `Low`, `Moderate`, or `High`. This object is designed to be consumed directly by downstream dashboards and the separate intervention repository.

## Explainability

The engine produces user-facing explanations from the highest-severity baseline deviations. It converts technical feature names such as `backspace_rate` and `fixation_duration_mean` into plain-English statements such as frequent typing corrections or longer visual fixation duration than the reference baseline.

The code imports SHAP when available for future model-specific attribution, but it does not expose raw SHAP values to users. The current endpoint exposes plain-English top contributing factors only.

## Recommendation Mapping

The inference layer does not generate exercises. It maps moderate and high learning-profile weaknesses to stable intervention category identifiers:

| Weakness | Module identifier |
| --- | --- |
| `reading_fluency` | `reading_fluency_training` |
| `letter_reversal` | `letter_reversal_training` |
| `spelling_accuracy` | `spelling_practice` |
| `typing_accuracy` | `typing_practice` |
| `phonological_processing` | `phonics_training` |

## API Response Contract

`POST /predict-full` and `POST /learning-profile` return the Phase 2.5 object:

```json
{
  "overall_risk": {"score": 0.84, "level": "High", "confidence": 0.91},
  "modality_scores": {"reading": 0.88, "writing": 0.74, "typing": 0.69},
  "baseline_comparison": {},
  "learning_profile": {},
  "top_contributing_factors": [],
  "recommended_modules": []
}
```

Clinical note: DysLexAI remains a screening-support prototype, not a diagnostic system.

## Domain-Shift Fix Addendum

A new domain audit module (`python -m src.mvp.domain_audit`) investigates the training-inference mismatch before any model changes. It verifies feature names, feature order, missing values, dtypes, and the serialized preprocessing contract. The training code saves a single sklearn `Pipeline` containing `SimpleImputer`, `StandardScaler`, and the classifier, so inference must continue loading that serialized pipeline rather than fitting new scalers.

The audit found that the committed processed tables include real-anchor rows for reading but no real processed rows for writing or typing. Because the trained `.pkl` artifacts are not present in this workspace and writing/typing real validation rows are unavailable, threshold recalibration and probability calibration are reported as skipped instead of inventing new thresholds from synthetic data.

The implemented minimum safe runtime fix is:

1. regenerate the baseline reference with normal operating ranges and percentiles;
2. validate all incoming inference features;
3. impute missing or non-finite values to non-dyslexic reference means to prevent crashes;
4. warn without clipping when values fall outside the reference validation range;
5. produce repeatable distribution-shift, threshold, calibration, and before/after reports.
